# 0.2.0 发布候选

本次将已合并的定时浏览主动分享功能制成独立的新版本，不覆盖 0.1.0 或 0.1.1 的标签和 Release 资产。0.1.1 已先行包含该功能和 Windows 支持；本候选合并保留这些改动，是否发布以对应 Release 为准。

- 成功的定时自主浏览会把最终发现交给宿主，在宠物空闲时显示气泡，保存一条聊天消息并创建关联驿站未读入口。
- 点击驿站定位原消息；重试和重启不重复通知。手动观看保持原有交付，失败、取消和跳过不主动分享。
- 产品内分享独立于 B 站评论/私信开关，不增加站外发送；仍默认关闭自主活动。
- 平台为 macOS Apple 芯片和 Windows x64，沿用 0.1.1 的双平台构建与原生验收，包含对应 FFmpeg、许可证与源码，权限没有变化。0.2.0 自身仍须完成下列最终包验证，不能借用 0.1.1 的验收回执。

## 宿主兼容范围

需要含 `pet.ai.share` 的桌宠兼容测试构建，当前集成验证基线为 Test 源码 `04fc78157edeb0c96415f9baaf6e98ff4c6c091a`。manifest 的 `minHostVersion: 0.30.0` 不能单独证明旧构建具备该接口；插件保留能力检测，不支持时面板会显示结果暂未送达。宿主仅通过受邀测试渠道提供。

## 发布顺序

1. 同步 manifest、package 和 lockfile 为 0.2.0，在公开分支运行既有 workflow_dispatch 构建候选。
2. 对 CI 生成的实际 ZIP 执行隔离宿主 Electron 验收，记录 SHA-256、大小和 CI run。
3. 有权限的上游维护者合并版本 PR，再推送 `v0.2.0` 标签，由现有工作流创建不可覆盖的 prerelease。
4. 下载实际 Release ZIP 并复算摘要、执行最终包验证，再更新官方市场条目及宿主预装清单。CI 候选的摘要不得冒充最终 Release 摘要。

本文件描述候选与发布步骤；源码提交、CI 成功均不代表已经发布或上架。自动化中的模型、账号及 B 站接口为本地测试夹具，不作为线上理解质量或站外发送的证明。
